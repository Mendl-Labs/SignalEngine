rebalancer-helm deployed: {{ include "rebalancer-helm.fullname" . }} (namespace {{ .Release.Namespace }})

This is the paper rebalancer driver loop (crates/rebalancer-service), NOT the main SignalEngine service. It is
paper-only, always (REBALANCER_PAPER_ONLY is hardcoded in this chart, not configurable), single replica, Recreate.
{{- if eq (toString .Values.serveProposalPlans) "true" }}

Mode: serveProposalPlans=true. It serves the approved paper strategy_plans of every tenant (a new approved plan gets a
runtime within about REBALANCER_REENUMERATE_SECS, default 300, no restart). Tenant paper keys arrive through the
credential broker ({{ .Values.credentialBroker.secretName }}); this pod holds no brokerage key of its own and never
CREDENTIALS_ENCRYPTION_KEY.
{{- if eq (include "rebalancer-helm.pilotPresent" .) "true" }}
The owner pilot pair is also served:
  tenant:  {{ .Values.pilot.tenantId }}
  account: {{ .Values.pilot.accountId }}
{{- else }}
No owner pilot pair is configured (proposal plans only); "no account is eligible yet" at start is normal.
{{- end }}
{{- else }}

Mode: owner pilot only. It serves exactly ONE allow-listed (tenant, account) pair:
  tenant:  {{ .Values.pilot.tenantId }}
  account: {{ .Values.pilot.accountId }}
{{- end }}

Check it's running and ticking:
  kubectl -n {{ .Release.Namespace }} get pods -l {{ include "rebalancer-helm.selectorLabels" . }}
  kubectl -n {{ .Release.Namespace }} logs -l {{ include "rebalancer-helm.selectorLabels" . }} -f

Every log line is prefixed "rebalancer-service:" (main.rs's own log() helper) -- heartbeats print once per tick
(default every {{ .Values.pilot.tickSecs }}s) even when nothing is due to run.
{{- if eq (include "rebalancer-helm.pilotPresent" .) "true" }}

Owner pilot only: before the pair can be eligible, the owner-authored `rebalancer_pilot_plans` / `mandate_events` rows
must exist in Postgres. Print the SQL template (no network call, no database connection) with:
  kubectl -n {{ .Release.Namespace }} run rebalancer-pilot-template --rm -it --restart=Never \
    --image={{ .Values.image.repository }}:{{ .Values.image.tag }} \
    --command -- rebalancer-service pilot-template

And confirm the connected paper Alpaca key's fingerprint (never prints the key itself) BEFORE authoring that row's
credential_fingerprint column, using the same Alpaca secret this Deployment uses:
  kubectl -n {{ .Release.Namespace }} run rebalancer-pilot-fingerprint --rm -it --restart=Never \
    --image={{ .Values.image.repository }}:{{ .Values.image.tag }} \
    --env="PILOT_ALPACA_KEY_ID=$(kubectl -n {{ .Release.Namespace }} get secret {{ .Values.secrets.alpaca.secretName }} -o jsonpath='{.data.{{ .Values.secrets.alpaca.keyIdKey }}}' | base64 -d)" \
    --env="PILOT_ALPACA_KEY_SECRET=$(kubectl -n {{ .Release.Namespace }} get secret {{ .Values.secrets.alpaca.secretName }} -o jsonpath='{.data.{{ .Values.secrets.alpaca.keySecretKey }}}' | base64 -d)" \
    --command -- rebalancer-service print-fingerprint
{{- end }}

The database role must hold the grants in databaseschema-internal scripts/rebalancer_pilot_ledger/role.sql (including the
rebalancer_bar_* tables the latency recorder uses, and alert_* when ALERTS_ENABLED).

This chart deploys nothing by itself -- it only renders manifests for whatever `helm install`/`helm upgrade` you run.
The image workflow (.github/workflows/rebalancer-service-image.yml) prints the install command in its build summary.
